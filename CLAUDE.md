# CLAUDE.md

Guidance for working in this repository.

## What this is

Tacet is a real-time, local-first macOS meeting assistant. It captures system
audio + microphone via ScreenCaptureKit, transcribes and diarizes entirely on
the local machine (Whisper for speech-to-text, ECAPA-TDNN for speaker voice
clustering), and sends only text transcript windows (and, when enabled,
downscaled screen frames) to your configured LLM provider for live insights,
chat, and end-of-meeting summaries. Audio is never written to disk or sent
anywhere. It ships two ways from one backend:

- **Electron desktop app** (`electron/`) — the end-user product; self-contained,
  spawns and manages the Python server, with all config in a Settings page and a
  first-run onboarding wizard.
- **Local web server** (`start.sh`) — the development surface: FastAPI/Uvicorn
  serving the built frontend at `http://localhost:8000`, configured via `.env`.

## Architecture

```
Swift CaptureHelper (bin/capture-helper, ScreenCaptureKit)
  → system audio (0x01), mic (0x04), screen frames (0x02) over a binary protocol
        │
  AudioCaptureSource (audio_capture.py) — manages the subprocess
        │
  WhisperTranscriber ×2 (transcriber.py) — Silero VAD → Whisper backend
        │           (mic="You", system="Speaker N"; shared GPU lock)
        │   SpeakerEmbedder (speaker_embedder.py) — ECAPA-TDNN voice clustering (CPU)
        │
  MeetingEngine (engine.py) — bleed dedup, analysis every N segments, chat,
        │                      summary, session persistence, knowledge vault
  LLMService (Bedrock | OpenRouter | Venice | Ollama) — streaming + tool use + prompt cache
        │
  FastAPI WebSocket (main.py) — single /ws connection; engines persist per
                                client_id across reconnects; serves static/
```

`llm_service.py` exposes the provider-neutral interface; `create_llm_service()`
selects the backend from `LLM_PROVIDER` (OpenRouter by default; OpenRouter,
Venice, and Ollama are OpenAI-compatible; `bedrock` runs through the official
Anthropic SDK's Bedrock client and uses `anthropic.`-prefixed model IDs). Ollama
requires no API key and runs fully on-device; set `OLLAMA_MODEL` (default
`llama3.1`) and optionally `OLLAMA_BASE_URL` / `OLLAMA_FAST_MODEL`.

Frontend is vanilla JS (`web/frontend/`), built by Vite into
`web/backend/static/` (gitignored; regenerated by build). All client↔server
traffic is one WebSocket; there are no REST endpoints.

The Electron main process (`electron/main.js`) picks a free port (prefers 8000),
spawns `uvicorn` from `.venv` as a detached process group, health-checks it,
loads the served URL, and reaps the whole group on quit. Settings persist to
`userData/config.json`; provider API keys are stored encrypted via the OS
keychain (`safeStorage`). Saved values are injected as env vars into the server
process; `electron/config.js` is the single source of truth for the settings
schema.

## Whisper backend

Auto-selected by chip (`whisper_backend.py`): mlx-whisper on Apple Silicon
(Metal GPU), faster-whisper on Intel (CPU). On Intel, `main.py` imports
`ctranslate2` before torch and sets `KMP_DUPLICATE_LIB_OK=TRUE` to avoid an
OpenMP duplicate-runtime abort. Override with `WHISPER_BACKEND=mlx|faster-whisper`.

## Commands

```bash
make setup                                  # one-time setup (runs ./setup.sh)
make app                                    # run the desktop app — THE product
make dev                                    # dev server at http://localhost:8000
make test                                   # backend tests
make build                                  # rebuild frontend

# Raw equivalents:
./setup.sh                                  # one-time: venv, deps, frontend, Swift binary, models
./start.sh                                  # run the web server (http://localhost:8000)
cd electron && npm install && npm start     # run the desktop app
cd web/frontend && npm run build            # rebuild frontend after editing it
cd web/frontend && npm run dev              # Vite dev server (proxies /ws to :8000)
.venv/bin/python -m pytest web/backend/tests/ -q   # backend tests
```

After editing anything in `web/frontend/`, rebuild — the server serves the
built bundle in `web/backend/static/`, not the source.

## Configuration

All config is env-var driven (read directly in the backend modules). Key ones:
`LLM_PROVIDER` and the matching provider keys (Bedrock: `AWS_BEARER_TOKEN_BEDROCK`
or `AWS_REGION`/`AWS_PROFILE` + `BEDROCK_*` model IDs; OpenRouter/Venice:
`*_API_KEY` + `*_MODEL`; Ollama: `OLLAMA_MODEL`, `OLLAMA_BASE_URL`,
`OLLAMA_FAST_MODEL` — no key required), plus `WHISPER_BACKEND`, `MEETINGS_DIR`,
`KNOWLEDGE_DIR`, `HF_TOKEN`, `WS_AUTH_TOKEN`, `LOG_CONTENT`, and the
`AUTOSTOP_*` thresholds. In
the desktop app these come from the Settings page; for the web server they come
from the environment / `.env`. When adding a new option, wire it in the backend
module **and** add it to `electron/config.js` so both surfaces expose it.

## Conventions

- Prefer the dedicated tools over shell `cat`/`sed`. Match surrounding style.
- Keep `MeetingContext` (`meeting_context.py`) as the meeting-metadata value
  object — it is core, not tied to any calendar integration.
- WebSocket origin checks accept any localhost/127.0.0.1 port plus Electron's
  null/file origins (the server port is dynamic under Electron). When
  `WS_AUTH_TOKEN` is set, every `/ws` connection must also present it.
- The LLM layer is provider-neutral: reach it through `LLMService`, never a
  specific provider client. Model tiering is a frontier model for
  chat/analysis/summary and a fast/cheap model for background extraction; vision
  uses its own model. All model IDs are env-overridable.
